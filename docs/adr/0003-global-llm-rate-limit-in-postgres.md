# Global LLM rate limit as a sliding window in Postgres

The LLM allows 60 requests per minute for the whole service, across every worker thread and replica. We keep a sliding-window log of call start times in Postgres, serialised by a transaction-scoped advisory lock: a caller may start a call only if fewer than 60 started in the last 60 s, otherwise it waits until the oldest one leaves the window. Time comes from the database (`clock_timestamp()`), the one clock every replica shares. A worker keeps renewing its Ticket's lease while it waits for a slot, so a long wait never lets another worker take the Ticket over and spend a second call on it. A token bucket was rejected because a full bucket plus refill allows up to ~120 calls inside one 60-second window; an in-process limiter was rejected because it breaks as soon as there are two worker replicas. The no-API-key mode goes through the same limiter, since the rest of the system must behave identically.
